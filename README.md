# 走航观测覆盖服务

海洋资料员上传某航次的走航观测点列（航次号 + 带严格递增 UTC 时刻的经纬度点），
服务按 **UTC 日** 和 **整度经纬格** 切分覆盖并存入 SQLite；
查询时给出某日、某格，返回与卫星记录对照用的合并观测时段。

## 切分与归属规则

- 相邻点之间视为持续观测，位置（含时间）随时间**线性插值**。
- 经度走**短弧**；若某航段两端短弧经差**恰为 180°**，整次提交拒收（HTTP 400，不写库）。
- 按 UTC 午夜、整度经线、整度纬线三类边界切分，切点重合（同一时刻跨多条边界）自动去重。
- 格用其**西边界经度**（-180..179）与**南边界纬度**（-90..89）标识；西、南边界归本格。
- 每个分片以其**中点**定格：切点保证分片内部不再含整度边界，因此朝西/南运动且
  起点恰好压线时，分片仍归入其内部实际所在的格。
- **±180° 视为同一条经线**：经度 180 归入西边界为 -180 的格。
- 只保留有时长的分片。
- 时刻必须带时区，服务统一转 UTC；不带时区直接 422。

## 事务与一致性

- 重交航次：单事务 `BEGIN IMMEDIATE` 内先删该航次全部分片、再插入新分片；
  其他航次不受影响。
- 计算失败（在写库前抛出）或保存失败（事务回滚）都保留旧覆盖，查询不受影响。
- 查询在单一只读事务（同一已提交快照）内完成；WAL 模式下读写互不阻塞，
  未提交的数据对查询不可见。
- 同一日/格的多个航次、多个分片时段按重叠或首尾相接合并后返回。

## 启动（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000/docs
```

SQLite 数据保存在命名卷 `coverage-data`（容器内 `/data/coverage.db`）。

本地无 Docker 时：

```bash
pip install -r requirements.txt
COVERAGE_DB=./coverage.db uvicorn app.main:app --reload
```

## /docs 演示流程

### 1. 上传航次 `PUT /voyages/{voyage_id}/coverage`

跨 180° 经线示例（179°E → 179°W，短弧向东 2°，1 小时）：

```json
{
  "points": [
    {"ts": "2026-11-20T00:00:00Z", "lat": 0.0, "lon": 179.0},
    {"ts": "2026-11-20T01:00:00Z", "lat": 0.0, "lon": -179.0}
  ]
}
```

再上传一个跨 UTC 午夜、同时跨整度线的航次：

```json
{
  "points": [
    {"ts": "2026-11-20T23:30:00Z", "lat": 10.2, "lon": 10.2},
    {"ts": "2026-11-21T00:30:00Z", "lat": 11.8, "lon": 11.8}
  ]
}
```

对同一 `voyage_id` 再次 PUT 即**整船更正**：旧分片在一个事务内全部换掉。
尝试经差恰为 180° 的航段会收到 400，且库中旧数据不变。

### 2. 查询 `GET /coverage`

参数：`day=YYYY-MM-DD`（UTC 日）、`lat_cell`（格南边界 -90..89）、
`lon_cell`（格西边界 -180..179）。

```
GET /coverage?day=2026-11-20&lat_cell=0&lon_cell=179
GET /coverage?day=2026-11-20&lat_cell=0&lon_cell=-180
```

返回合并后的起止时刻（UTC，ISO 8601，`Z` 结尾）。

### 3. 辅助查看 `GET /voyages`

按航次/日/格列出分片数量与时间范围，便于核对写入结果。

## 测试

```bash
python -m pytest tests/ -v
```

覆盖：跨午夜/跨格切分、西南边界归属、跨 ±180 短弧、180 同线归属、
180° 经差拒收、时刻/坐标校验、重交原子替换、计算与保存失败保留旧结果、
多航次时段合并、已提交快照隔离、极点夹格，以及 300 条随机轨迹的时长守恒不变量。
